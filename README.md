# Wine Quality Prediction Web Application

A Django-based machine learning system with role-based access control, built for the
BSc Artificial Intelligence coursework project (Binay Chaudhary, 25123792).

## What's included

```
wine_quality_project/
├── manage.py
├── requirements.txt
├── wine_quality_project/       # Django project settings/urls
├── predictor/                  # Django app (models, views, forms, templates, ml_model.py)
├── data/WineQT.csv             # Dataset (1,143 rows, 13 columns)
├── model/                      # Serialized model + scaler + metadata (generated by the notebook)
└── notebooks/
    ├── wine_quality_analysis.ipynb   # EDA, model training, evaluation, model export
    └── train_script.py               # Same pipeline as a plain .py script
```

## 1. Setup

```bash
python -m venv venv
source venv/bin/activate        # venv\Scripts\activate on Windows
pip install -r requirements.txt
```

## 2. Train the model (if `model/wine_quality_model.pkl` isn't already present)

Run every cell of `notebooks/wine_quality_analysis.ipynb`, or simply:

```bash
python notebooks/train_script.py
```

This trains Logistic Regression, Random Forest and Gradient Boosting classifiers on
`data/WineQT.csv`, evaluates them (accuracy, macro precision/recall/F1, macro ROC-AUC),
and saves the best-performing model (selected on macro F1 — Random Forest in the
report) to `model/wine_quality_model.pkl`, along with `scaler.pkl` and
`model_metadata.json`.

## 3. Set up the database and an administrator account

```bash
python manage.py migrate
python manage.py createsuperuser
```

The superuser account (`is_staff`/`is_superuser`) can access the Admin Dashboard at
`/admin-dashboard/`. Regular users who register via `/register/` only see their own
prediction history.

## 4. Run the server

```bash
python manage.py runserver
```

Visit http://127.0.0.1:8000/

- `/register/` — create a regular user account
- `/login/` — log in
- `/predict/` — submit the 11 wine measurements and get a predicted quality score
- `/result/<id>/` — view a single prediction result
- `/dashboard/` — the logged-in user's own prediction history
- `/admin-dashboard/` — staff/superuser view of all registered users and predictions
- `/admin/` — Django's built-in admin site (also staff-only)

## REST API (Django REST Framework)

All endpoints require login (session, i.e. log in at `/login/` first, or HTTP Basic Auth from Postman/curl).

| Method | Endpoint | Access | Purpose |
|---|---|---|---|
| POST | `/api/predict/` | any logged-in user | Send the 11 measurements as JSON, get the predicted quality back |
| GET | `/api/predictions/` | any logged-in user | Your own prediction history |
| GET | `/api/predictions/<id>/` | owner or admin | A single prediction |
| GET | `/api/admin/predictions/` | admin/staff only | All prediction records |
| GET | `/api/admin/users/` | admin/staff only | All registered users |

Example (curl, Basic Auth):

```bash
curl -u yourusername:yourpassword -X POST http://127.0.0.1:8000/api/predict/ \
  -H "Content-Type: application/json" \
  -d '{"fixed_acidity":7.4,"volatile_acidity":0.7,"citric_acid":0.0,"residual_sugar":1.9,"chlorides":0.076,"free_sulfur_dioxide":11.0,"total_sulfur_dioxide":34.0,"density":0.9978,"ph":3.51,"sulphates":0.56,"alcohol":9.4}'
```

You can also open `http://127.0.0.1:8000/api/predict/` in the browser after logging in and use DRF's browsable API form.

## Notes

- The target `quality` variable has 6 classes (3–8) and is imbalanced, so macro-averaged
  metrics are reported alongside accuracy (see the report/notebook for the full comparison
  table).
- `Id` is excluded from model training — it's a row identifier, not a feature.
- The database defaults to SQLite for local development, as recommended in the report's
  Future Scope for eventual migration to PostgreSQL.
